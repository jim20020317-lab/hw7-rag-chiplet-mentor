## 1. 一頁速覽：DCIM 分割的 10 條核心原則

|---|---|---|
| P1 | **容量決定 regime，不是切割技巧決定**。`C_CIM ≥ W_model` → model-stationary（無 runtime weight update）；`W_model > C_CIM ≥ W_layer` → layer-stationary；`C_CIM < W_layer` → tile-stationary。regime 一跳出去，weight reload 就變成不可與 compute 重疊的一級成本。 | TriCIM（L1）Table I/Fig.3，p.2189；TriCIM PDF p.5（目視）；model-stationary 相對 CiMLoop 2.8–13.2× speedup、16.2–86.7× energy（L1 p.2197） |

## 2. 分割軸完整清單（partition axis catalogue）

> 分三類避免混淆：**A 類（邏輯/張量軸，真正切資料）**、**B 類（配置軸，切硬體資源）**、**C 類（後果軸，描述切完代價落點）**。每個軸寫「切了會發生什麼／什麼時候該切／陷阱」。

### A 類：邏輯 / 張量軸

#### AX-N（output channel / `C_OUT` / `dout`）
- **切了會發生什麼**：每個 compute 單元只需自己那份 output-channel weight → **weight 不複製、不重載**；代價轉到 **activation broadcast / all-gather**。切 N 是**輸出維，不產生跨分割 reduction**。
- **什麼時候該切**：單層放不下、又不想付 reduction 時的第一刀。INDM 的 K-Parallel（K＝輸出通道）把 weight 分散、activation 用 (3/4)·P·Q·K 的 all-gather；FLARE Column-wise（Broadcast ✓ / Reduction ✗）。
- **陷阱**：activation all-gather 打在本已最大的 activation buffer 能量項（Sun activation buffer 38%）。不要把它跟 activation 複製（= 每份都要一份完整 activation）混淆；broadcast/multicast（源 1×、sink D×）比落地複製便宜。[E] L7 p.1112/Fig.5；W3 FLARE Table II；L2 Fig.4

#### AX-K（contraction / input channel / `N_WPF`）
- **切了會發生什麼**：**必產生第二級 reduction**。in-situ 只能吃 `≤R`；超出後跨 fold 的 partial sum 走 accumulator buffer（每 fold 1R+1A+1W），跨 macro 走 channel accumulator / FAN adder tree，跨 die 走 AllReduce。切 K 通常 weight 不複製。
- **什麼時候該切**：**只在 die 內、且 N/M 都切不動（容量或利用率）時**。作為 `K > R_insitu` 時的 fold 手段是必要的（P3）；作為跨 die 的切法則是最後手段（P5）。
- **陷阱**：① 把「K 一定映到 rows」當通則——PolyCIM 的 macro 是 row-wise input broadcasting + column-wise output accumulation，收斂軸映到 columns，fold 應是 `FC=ceil(K/C)`（R1 §OG-9）。② 以為跨 die 切 K「反正有 NoC」——deadlock 與 24-bit psum 流量是結構性成本。[E] L2 Eq.(5)(14)；L3 Table IV/V；L5 channel accumulator；W2 PolyCIM §3.4.1；R1 §OG-9

#### AX-M（spatial / output pixel `P/Q` / `OH·OW`）
- **切了會發生什麼**：不同 output pixel 不互相加 → **不產生 output reduction**；代價是**每個 die 需完整 weight（weight replication）**＋conv 層界 **halo（S−1 欄）unicast**。
- **什麼時候該切**：activation size 夠大、spatial 平行度能被吃滿時優先。INDM P/Q-Parallel weight multicast；FLARE Row-wise 其實切的是 `din`（收縮）並只做 output reduction，**不是純 M**——兩者要分清。
- **陷阱**：① 對 attention 層，sequence 軸同時是 query row（M）與 `QK^T`/softmax 的收斂維（K），切它會引入 row-wise reduction（HiRe softmax horizontal sync、Zexin INR）。② spatial 切太細 → 小 activation 層利用率崩（INDM「P-Parallel may not be optimal for layers with a small activation size」）。[E] L7 p.1110/Fig.10(a)；L4 §II.B/V-B；W3 FLARE Table II；R1 §OG-3

#### AX-B（batch / token / sequence / timestep）
- **切了會發生什麼**：由構造**不產生 reduction**（樣本獨立）；**weight 複製到每個分割**；sequence 切塊有 cross-block 依賴（softmax row 依賴、FlashAttention 式 local softmax + global normalization）。
- **什麼時候該切**：**吞吐擴展最便宜的軸**；HiRe 對 DNN 用 data-parallel weak scaling。batch 也可攤銷 weight reload（TriCIM batch 1→16，相對改善 1.06×→1.29×）。
- **陷阱**：sequence 切塊的依賴會限制 pipeline 深度；LLM 的 KV cache 使「切 sequence」同時要決定 KV 駐留（見 AX-KV）。[E] W3 FLARE Table II（Sequence: Replication ✓）；L7 HiRe p.1739；L1 Fig.16；L4 §VI-B

#### AX-BIT（weight bit / activation bit / block-FP exponent）
- **切了會發生什麼**：有兩種正交實作——**spatial（沿 column 展開）**：更多 column/ADC converts，跨 bit-slice 用 shift-and-add；**temporal（沿 cycle 展開）**：accumulator＋shift-add、DAC 可簡化為 1-bit，latency × bit 數。
- **什麼時候該切**：單一 cell 精度不足（ISAAC `16/w` 個 w-bit cell）、或要把「一次能吃的 K」換成「多 cycle shift-add」以避開跨 die reduction。block-FP 用共享 exponent 攤銷（Wang `INCIM=16`，精度 −0.86%）。
- **陷阱**：① 忽略 bit-serial 週期放大（8-bit activation、s=1 → 8 cycles；partition 成本函式不含 `n_cyc` 會嚴重低估 K fold）。② 把非分割技巧（RAELLA center+offset 平移、Wang low-toggle 數值重分群、MDM row 排序）誤列為 bit 分割。[E] W1 A3/A4/A5/A7/A9/A10；L2 Table IV p.1197；L5 §II.A/Fig.6；L3 p.1222；R1 §3.2-3

#### AX-LAYER（layer / operator / subtask / stage）
- **切了會發生什麼**：以 layer/operator 為最小單位 → **由構造無跨 die reduction**；layer 邊界需 weight reload/reprogram；層間傳 activation。
- **什麼時候該切**：**只要單層 footprint 放得進單 die，首選切 layer**（跨 die 的安全預設）。SIAM 明文「DNN layer 不可跨 chiplet 切」。
- **陷阱**：layer-stationary 的群間重載粒度是**整個 CIM tile、full-matrix、無 partial update**，且同 macro 內不可與 compute 重疊；必須用 ping-pong/overlapped reload 排程。[E] W3 SIAM §2.2；L1 §V-B p.2193；W3 §4.2

#### AX-MODEL（model / regime）
- **切了會發生什麼**：不切單一 tensor，而決定「哪些層權重常駐 on-chip」。model-stationary → 無 runtime reload；layer-/tile-stationary → 有 runtime reload。
- **什麼時候該切**：**第一步就該先判定**（P1 根節點）。同一模型在 ISAAC-Large(504MB) 落 model、ISAAC-Medium(63MB) 落 layer、AdaPIM(0.72MB) 落 tile。
- **陷阱**：用整塊 array 容量當 `C_CIM` 會誤判——必須扣掉 activation/KV/psum 佔用與 memory-mode 保留（見 AX-MODE）。[E] L1 Table I/Fig.3/Fig.11；R1 §OG-5

#### AX-SP — sparsity-aware partitioning（★R1 新增，T1/T2 原缺）
- **切了會發生什麼**：稀疏度改變**有效 K 與有效 tile 數**。若要真省 adder tree 能量，**skip 粒度必須＝array 的一整條 K 段**，否則 adder tree 仍全開。
- **什麼時候該切**：activation 稀疏度高時。Wang DBS-H「patch-channel skip」以 `patch = OUTCIM×INCIM` 為粒度整 patch/整 channel 跳過；FlexSpIM 輸入稀疏 85–99% 下省 87–90% 能量；H3D-LLM SADEF 用動態 1-bit mask；TensorCIM SpG 重排/重分割使 gathering 走本機 DRAM。
- **陷阱**：`FR=ceil(K/R)` 不含 ρ，對 >80% 稀疏層會**高估 fold 與 accumulator 交易**。patch skip rate 在 ViT-B 僅 0.005–0.02、EViT 最高 ~0.25——**稀疏度低時 skip 幾乎無效**；LA(ReLU) 稀疏度 >80% 才有高 skip 機會。[E] L5 §III.B.3 p.8/Fig.16/25；L6 §III.B Fig.7(c)(d)；W3 卡#14；W3-10 Fig.16.4.3

#### AX-PREC — precision-elastic partitioning（★R1 新增）
- **切了會發生什麼**：精度是可切的 tile 變數。LRMP 決策變數＝每層 replication factor `r_l` ＋ 每層 mixed-precision `s_l`，LP 約束 `Σ r_l·s_l ≤ N_tiles`；**降精度是為了釋放 tile 去複製**。H3D PAQM channel-level mixed precision（DCIM INT8、ACIM INT4、BF16 outlier）。
- **什麼時候該切**：tile 預算不足、且某些層對精度不敏感時。
- **陷阱**：精度不對稱會改變 cell 佔用與等效 MAC 數（Sun IS 下 16-bit activation 佔 16 cells → 等效 MAC 砍半）。[E] W2 D4 LRMP Eq.7/8；W3 卡#14；L2 p.1198；R1 §1.2

#### AX-KV / dynamic-weight（★R1 新增，T1/T2 僅一行帶過）
- **切了會發生什麼**：KV cache 與 dynamic weight 的分割與駐留。dynamic weight 不能與 static weight 共用同一份 array（需兩份 array 或 ping-pong rotation）。
- **什麼時候該切**：LLM/attention 為目標時必問：「KV 放哪一級、幾層、是否常駐、如何隨 sequence block 遷移」。
- **陷阱**：FLARE Parallel Mode 保留所有 tensor（含 KV cache）vs Pipelined Mode（transient）；H3D SATS 用 correlation-scored tiered KV cache；TriCIM pipeline mode 給 K/V 各兩組 CIM array（一組算、一組存下一輪）；Wang DBS-F 固定 256 tokens。**「KV cache 在 CIM 上」是與 compute 無關的 capacity 決策**。[E] W3-1 p.504–505；W3 卡#14；L1 §VI-B/§VIII-C p.2195–2199；L5 §III.A/Fig.13；R1 §1.3/§1.4

### B 類：配置軸（切硬體）

#### AX-HW（macro 幾何 / cluster 粒度 / buffer 配比 / tile 預算）
- **切了會發生什麼**：調 `R×C`、`N_core/N_macro`、`L1base`/`ratioL1_W:A:O`/`ratioL2`、cluster 尺寸、gear macro。`R↓`→accumulator 交易↑、energy↑；`C↑`→IS 的 `ceil(N_OF/C)` weight reload↓；buffer 中 weight 佔比↑→reload↓但可容 activation tile↓→spatial 切更細、halo↑。
- **什麼時候該切**：固定容量下的 PPA 取捨。Sun 固定 2304 MAC 可 retile 144×16 / 72×32 / 36×64 / 18×128 / 9×256；**36×64 平均利用率最高、72×32 平均 EDP 最低（workload 相依）**。SynDCIM 在 timing 不足時把 column `H→H/2`（timing-driven fallback，非效能導向）。
- **陷阱**：把幾何結論當通則——EDP/util 最佳點高度 workload 相依。[E] L2 Fig.13 p.1198–99；L7 INDM Table V p.1117；L7 HiRe §III-A；W2 SynDCIM §III-C；W3 AIG-CIM；R1 §OG-10

#### AX-OP（operand-role stationarity：WS / IS / OS）
- **切了會發生什麼**：決定「哪個 operand 留在 CIM array、哪個被串流」。WS（weight-stationary）、IS（input-stationary）、OS（output/membrane-potential stationary）。**stationarity 是資料流選擇，不是 DCIM 的物理天性**。
- **什麼時候該切**：DW-CONV / `C_IN` 小 → 選 IS（columns 對 output pixel，16/16 columns 全開），否則 WS 下 15/16 columns idle；per-layer 可換（FlexSpIM 為 SNN 用 WS/OS hybrid）。
- **陷阱**：① 認為「DCIM 天生 weight-stationary」——Wang DBS 是 input-stationary + weight-bit-serial；FlexSpIM per-layer WS/OS。② dataflow 切換有硬體成本（Sun ~0.12% macro 面積）與精度不對稱代價。[E] L2 p.1194/1198/Table V/Fig.12；L6 §II；L5 Table I；R1 §OG-8

### C 類：後果軸

#### AX-ST（spatial vs temporal，meta-axis）
- **切了會發生什麼**：幾乎每個 A 類軸都可選 spatial（同時並行、更多硬體/資料複製）或 temporal（同一硬體分時、需 accumulator/序列化）。
- **什麼時候該切**：ISAAC 明言「若晶片上有一半 IMA 未使用，就複製所有權重、吞吐約翻倍」——**只有空閒硬體才值得 spatial 複製**。[E] W1 A4/A9；L2 Fig.15；L6 §II

#### AX-RED（reduction 收斂點）
- **切了會發生什麼**：決定 partial sum 在哪一級收斂。層級由低到高：`array in-situ adder tree → macro accumulator buffer → tile FAN adder tree → NoC in-network reduction → die global accumulator → 跨 die AllReduce → 退回 DRAM`。
- **什麼時候該切**：**永遠優先選最低可行層級**（P3/P8）。跨 die reduction 的替代只有三種：不切收縮維 / reduction 結果 reuse 留 CIM（TensorCIM REGM）/ 顯式 AllReduce（Corsair）。
- **陷阱**：退回 DRAM 是最差選項，未見任何論文主張。跨 die reduction 的硬體機制多半「原文未提供」（FLARE row/2D/3D 標 Output Reduction ✓ 但機制未描述）。[E] L2 Eq.(14)/Fig.15；L3 Table V；L4 INR §V-B；W3 TensorCIM/Corsair；W3 §5-2

#### AX-W（weight 處置）
- **切了會發生什麼**：stationary（不重載）/ replication（multicast）/ slicing（分散）/ reload（reprogram）。與 activation 處置是零和交換。
- **什麼時候該切**：判準不是 bytes，而是「此 operand 是否需 reprogram CIM array」。DCIM 的 1-bit weight reprogram 成本 ≫ 1-bit activation streaming，且不可與 compute 重疊。[E]/[I] W3 §4.3；L2 p.1197（>4MB → DRAM double-buffer）；L1 §V-B

#### AX-AB（activation 處置）
- **切了會發生什麼**：broadcast（multicast，源 1×、sink D×）/ all-gather / streaming（unicast/halo）。
- **什麼時候該切**：切 N 時必須 broadcast/all-gather；切 M 時只需 halo unicast（conv 層界 S−1 欄）。multicast 優於落地複製。[E] L7 p.1112/Fig.10(a)；W3 FLARE Table II

#### AX-MODE（dual-mode：compute vs memory，★R1 新增）
- **切了會發生什麼**：每個 CIM array 可為 compute(`λ_c`)/memory-input(`λ_min`)/memory-output(`λ_mout`)，`2^m` 種模式；成本顯式含 mode-switch latency `L_{M→C}, L_{C→M}`、write-back、weight rewrite。
- **什麼時候該切**：LLM 推論時「compute to memory ratio in CIM arrays about 10%」→ 寧可提供更多 on-chip random memory 放 activation 與 KV cache。
- **陷阱**：把整塊 array 容量都當 compute 容量會誤判 regime（見 P1 陷阱）。[E] W2 C2 CMSwitch Eq.1–3；webtext/2502.17006v1；R1 §1.3

#### AX-REC（runtime reconfiguration / shape-switch 成本，★R1 新增）
- **切了會發生什麼**：動態重構鏈路/形狀的成本。Sun FDN/FAN 每 workload 一次重配置（面積 ~6% macro、energy <1%），但 4×1 vs 1×4 的 buffer BW 差 4×；HiRe RN reconfigure 無壅塞時 1 cycle 完成 4 步、但可連範圍受限（X/Y 差 ≤1）；FlexSpIM NR/NC 由 2-bit control bitcell 在 runtime 設定。
- **什麼時候該切**：形狀切換頻率 × switch 成本 < 靜態 mapping 損失時，動態重構；**權重「搬家」成本 > 鏈路/形狀重構成本時，改重構鏈路不搬 weight**（HiRe 原則）。[E] L2 p.1200/Fig.17；L7 §III-B p.1741；L6 §II；L5 Fig.5 p.3；R1 §1.5

## 4. 決策樹（可直接實作）

> **規則標記**：`[E]` 有實驗支持、`[I]` 推論需驗證。**本節已修正 T2 的 `F1`（軸↔代價三分）、`B1`（PolyCIM reuse 軸標定）、`E3`（跨 die K 降級為最後手段）、hold factor、`C_CIM_eff`。**

### 4.1 主流程偽代碼

```python
DECIDE(layer L{M,N,K,A_bits,Wt_bits,B,kind,sparsity ρ}, 
       hw{Rp,Cp,Rh,Ch,R_M,C_M,C_total,B_buf,s_bits,level_capacity}):

# ── Stage 0：正規化（每個 A 類軸的週期成本都含 n_cyc）────────────
    n_cyc = ceil(A_bits / s_bits)                      # [E] Sun Table IV；L5 §II.A
    W_layer = K*N*Wt_bits
    W_model = Σ_layers W_layer                          # 呼叫方提供
    K_eff   = K * (1 - ρ)   # 只在 skip 粒度＝整條 K 段時可省 adder tree  # [E] L5-H/L6
    # DCIM 專屬：容量要扣掉非 compute 佔用
    C_CIM_eff = C_total - act_footprint - KV_footprint - psum_footprint \
                - memory_mode_reserved                    # [E] FlexSpIM Fig.4、CMSwitch；[I] 推廣

# ── Stage 1：容量 regime（根節點）───────────────────────────
    if C_CIM_eff >= W_model:      regime = MODEL_STATIONARY   # [E] TriCIM A1
    elif C_CIM_eff >= W_layer:    regime = LAYER_STATIONARY   # [E] TriCIM A2
    else:                         regime = TILE_STATIONARY    # [E] TriCIM A3

# ── Stage 2：切哪個軸（條件式，不是固定優先序）────────────────
    # 先問「activation 是否足夠大、spatial 利用率是否能吃滿」
    if kind == attention:                    # [E] HiRe/Zexin：sequence 軸 = M 且 = K
        sequence_axis_is_M_and_K = True      # softmax/QK^T 的 row reduction 不可跨 die
    if activation_size < theta_util:         # [E] INDM p.1113「P-Parallel may not be optimal…small activation」
        candidate = [AX_N, AX_LAYER]         # 改切 output channel / layer
    else:
        candidate = [AX_B, AX_M, AX_N, AX_LAYER]   # [E] FLARE Table II：seq/M 無 reduction
    # 只有候選都用盡才把 AX_K 放進 die 內候選；跨 die 時 AX_K 是最後手段
    if need_more_parallel and level == die:
        candidate += [AX_K]

# ── Stage 3：切幾份 × 放哪一級（各自層級公式不同，不可共用）─────
    if regime == MODEL_STATIONARY:
        parts = allocate_tiles(L, n_tile)        # [E] TriCIM C5 min_tile_l 公式
        level = TILE; reduction = ARRAY_ADDER_TREE
    elif regime == LAYER_STATIONARY:
        groups = group_layers(W_layer_list, C_CIM_eff)   # [E] TriCIM A6
        level = TILE; reload_granularity = FULL_TILE_FULL_MATRIX  # [E] TriCIM F3
    else: # TILE_STATIONARY
        (FR, FC) = fold_counts(L, Rp, Cp, Rh, Ch, R_M, C_M, axis)  # 修正版公式
        level = MACRO; reduction = ACCUMULATOR_BUFFER

# ── Stage 4：K 是否超過 in-situ 上限（逐層級）────────────────
    # 注意：先確認收斂軸映到 rows 還是 columns（PolyCIM 是 columns）
    R_insitu = Rp * R_M if reduction_axis_is_rows else Cp * C_M   # [E] Sharma Table IV
    if K > R_insitu:
        FR = ceil(K / R_insitu)                  # [E] Sun Eq.(5)
        reduction = ACCUMULATOR_BUFFER           # [E] Sun Eq.(14)：每 fold 1R+1A+1W
        assert reduction_level <= DIE_INTERNAL   # [I] 最後手段，非絕對禁忌（見 §4.3）

# ── Stage 5：reduction 放最低可行層級 ──────────────────────
    reduction = place_reduction(lowest_feasible_level)   # [E] Sun FAN / Zexin INR

# ── Stage 6：weight 處置（三分交換，修正 T2 F1）────────────
    if cut_axis == AX_N:      # output channel
        weight = SLICE;  cost = ACTIVATION_BROADCAST      # [E] FLARE col ✗/✓/✗
    elif cut_axis == AX_K:    # contraction
        weight = SLICE;  cost = OUTPUT_REDUCTION          # [E] FLARE row ✗/✗/✓（不複製 activation）
    elif cut_axis in {AX_M, AX_B}:
        weight = REPLICATE; cost = HALO_or_NONE           # [E] FLARE seq ✓/✗/✗
    # 判準不是 bytes：weight 是否需 reprogram
    if implying_reload:
        granularity = FULL_TILE_FULL_MATRIX                # [E] TriCIM
        schedule    = ping_pong if Tcomp/Twt < 0.5 else sequential  # [E] TriCIM I4

# ── Stage 7：跨 die 例外（僅當單 die 放不下）────────────────
    if W_layer > C_CIM_eff(die):
        level = CHIPLET
        axis  = AX_N (weight shard) or AX_M (halo)        # [E] INDM/FLARE/TSPP
        if axis == AX_N and unavoidable: reduction = ALLREDUCE  # [E] Corsair
        elif axis == AX_K: reduction = LAST_RESORT_ALLREDUCE    # [I] 非絕對禁忌
```

### 4.2 容量 regime 判定（含 `C_CIM_eff`）

| Regime | 判定式 | 行為 | weight 重載 | 對應優化 | 出處 |
|---|---|---|---|---|---|
| **Model-Stationary** | `C_CIM_eff ≥ W_model` | 全權重推論前載入、全層 pipeline | **無 runtime 重載** | load-balancing tile 配置、cross-layer scheduling | TriCIM（L1）Table I p.2189；**本檔目視** |
| **Layer-Stationary** | `W_model > C_CIM_eff ≥ W_layer` | 模型切 layer group，群內 pipeline、群間依序 | **群間需重載**（粒度＝完整 CIM tile、full-matrix、無 partial update） | layer grouping、overlapped weight reloading | L1 Table I/§V-B p.2193 |
| **Tile-Stationary** | `C_CIM_eff < W_layer` | 單層切 sub-tile 依序處理 | **每 tile 重載** | CIM-aware tiling、buffer-aware ordering | L1 Table I/§VI-A |

> **`C_CIM_eff` 修正理由**：DCIM 同一塊 array 常同時放 activation / membrane potential / dynamic weight。FlexSpIM unified weight/pot memory：L1 weight 0.1 kB 但 pot 96.0 kB；HS-min 23.4 kB vs WS-only 69.8 kB。若用整塊容量當 `C_CIM`，會在 HS/dual-mode/動態 KV 場景誤判為 model-stationary。[E] L6 Fig.4（**目視**）；W2 CMSwitch；[I] 修正式。

### 4.3 `K` 超過 in-situ 上限的處置（含層級與證據）

| ID | if-then | 層級 | 證據 |
|---|---|---|---|
| E1 | `K > R_insitu` → `FR = ceil(K / R_insitu)`（先確認收斂軸映 rows 還是 columns） | array→macro | [E] L2 Eq.(5)；**PolyCIM column-wise accumulation 為反例**（R1 §OG-9） |
| E2 | 每 fold 用 **accumulator buffer** 收斂（read-add-write）；`AB_RD/WR = N·M·ceil(K/R)` | macro | [E] L2 Eq.(14) p.1196 |
| E3 | **優先** die 內第二級 adder（accumulator/FAN/channel accumulator）；**其次** in-network reduction（Zexin INR）；**最後** 才 AllReduce。跨 die 切 K 是**最後手段、不是禁忌**：IN/FLARE-col/TSPP 都避免，但 Corsair TP+AllReduce 證明可做。 | array→chiplet | [E] L2 Fig.15；[E] L4 §V-B；[E] W3 Corsair p.32；[I] 降級修正（R1 §OG-6） |
| E4 | `R`（或 `Rp`）越小 → accumulator 交易越多、energy 越差；EDP 最佳點落在中間 | macro | [E] L2 Fig.13 p.1199；[E] L3 Table IV |
| E5 | 能效隨 K 上升到 `K=256`（Digital-6T `Rp=256`）見頂；`K>512`（on-chip 容量）後 TOPS/W plateau ~1.75 | array/memory | [E] L3 Fig.10c/p.1224–25（**註**：256 是 K sweet spot、512 是 weight matrix 大小 cap，**不同軸**，勿合併敘述——R2 註） |
| E6 | 若 K 超過 on-die 收斂能力且無法加大 R：優先 (a) weight 空間 bit-slicing 攤開，或 (b) input 時間 bit-serial 攤開；不要 (c) 跨 die 傳 partial sum | array | [I] 由 W1 A3/A4/A7 + E3 合成 |
| E7 | 若需 die 內第二級 reduction：用 INR 或 output buffer in-place reduction，但先做 deadlock 分析並保留 SIMD 回退 | tile/die | [E] L4 §V-B3；W3 Corsair p.35 |

### 4.4 軸選擇：條件式（不是 `N > M > K` 固定序）

- **PolyCIM 原文真實優先序**：output-reuse（對 GEMM = **K**，因 partial sum 位寬大、移動最貴）→ input-reuse（= **N**）→ non-reuse → weight-reuse（= **M**，可 replication、容量夠才用）。**T2 舊版把三個標籤全部錯位、方向相反**，本檔不採用。[E] W2 PolyCIM §3.4.2（**目視**）；R1 §OG-2
- **但不存在單一固定優先序**：INDM Table VII 同一 ResNet-18 內 Layer1 全切 P（spatial M）、Layer7/10/14 全切 output channel。**先問「此層 activation size 是否夠大、spatial 利用率能否吃滿」**——INDM 原文：「P-Parallel may not be optimal for layers with a small activation size」。[E] L7 p.1113/Table VII（**目視** Fig.8）
- **DW-CONV / 小 `C_IN`** → 選 **IS**（columns→output pixel，16/16 columns 全開），否則 WS 下 15/16 columns idle。[E] L2 p.1194/1198
- **attention** → sequence 軸同時是 M 與 K，softmax/QK^T 的 row reduction 不可跨 die。[E] L7 §III-B-2；L4 §II.B/V-B

### 4.5 有實驗 vs 推論（一句話）

**有實驗支持 `[E]`**：容量三分區（TriCIM 4 模型×4 硬體）、FLARE 的 ✓/✗ 矩陣、Sun 三種 floorplan 與 36×64/72×32、Sharma `Rp/Cp/Rh/Ch` 與 K=256/512、INDM P/Q/K 7-parallel 與 Table VII、Wang dual-bit/block-FP/patch-skip、FlexSpIM HS、Zexin INR、Corsair AllReduce 成本、TensorCIM REGM。
**推論需驗證 `[I]`**：跨 die 切 K 的「最後手段」定位、`C_CIM_eff` 修正式、DCIM 上 axis 優先序的**代價權重**、ping-pong 平行度減半對 end-to-end 的影響、FLARE/Tile Interleaving 的跨 die reduction 機制、DCIM-specific 跨 die cost model。

|---|---|---|---|---|

## 6. 陷阱清單（反例）

1. **切 contraction 維 `K` 當第一刀。** K 通常最大，但切 K 必產生 reduction；跨 die 時 24-bit psum 比 8-bit W/A 寬、inter-die 1 bit ≈ 49 個 8-bit MAC 能量。→ 先切 `N`/`M`。[E] L7 p.1109/Table III；W3 FLARE Table II
2. **預設複製 weight。** 空間切（M/sequence）確實需要複製 weight，但 DCIM 的 weight reload 是**完整 tile + full-matrix、不可與 compute 重疊**；只有 pipeline 平衡、空間輸入重用、提高平行度三種情況才划算。[E] L1 §V-B；W1 ISAAC A1/A4/A11
3. **用 bytes 當 partition 成本。** DCIM 成本主導項是 array 啟動次數、ADC convert 次數、buffer access、**reprogram 事件**。Hemlet GLP 交錯省 ADC 但 energy +4.62% 就是反例。[E] L4；W3 Hemlet §6.2；W2 CiMLoop
4. **層級混淆：把「macro 內 array 切法」套到 die 級（或反之）。** 例如把 ISAAC A2（**array 內** 256×256→4×128×128）直接當 Sun Fig.14（**tile 級** 4 顆獨立 macro＋FDN/FAN）——**R1 明確指出 T2 舊版 C9 曾畫等號**。[E] W1 ISAAC p.6；L2 p.1200；R1 §OG-7
5. **假設一定有獨立 columnwise adder tree。** FlexSpIM 用 column carry-chain、CASCADE 用 buffer 類比累加；方法不可直接移植。[E] L6；W1 CASCADE
6. **忽略 bit-serial 週期放大。** 8-bit activation、s=1 → 8 cycles；成本函式不含 `n_cyc` 會嚴重低估 K fold。[E] L2 Table IV
7. **只看平均 hop、不看最壅塞鏈路。** mapping 好壞由 bottleneck link 決定（INDM `degrade_ratio`）。[E] L7 Eq.(4)
8. **逐層貪心選切法。** 相鄰層切法不同會把層界通訊從 halo 升級成 all-gather；必須全域 DP。[E] L7 Eq.(5)
9. **忘記 spatial 切的 halo 成本。** conv 層界要傳 `S−1` 欄；sequence 切要複製 weight。[E] L7 Fig.10(a)；W3 FLARE Table II
10. **預設「一層可以跨 chiplet 切」。** SIAM 明文 layer 不跨 chiplet；Tile Interleaving 雖可切但把 reduction 跨到 die。[E] W3 SIAM §2.2、Tile Interleaving
11. **把 partial sum 當 activation 寬度處理。** psum 24/36-bit，移動比 activation 貴一個量級。[E] L7 p.1115；L2 Fig.2
12. **用 weight duplication 取代 activation replication（或反之）而不比較。** 兩者零和；DCIM 判準是「哪個 operand 需 reprogram array」。[E] W3 §4.3
13. **認為多 macro 的 K 切免費（反正有 FAN）。** 4×1 垂直堆疊需 2-stage FAN 且 buffer 頻寬 ×4 → memory-bound；1×4 multicast 只需 1× 頻寬且無跨 macro reduction。[E] L2 Fig.15/17（**目視**）
14. **忽略 ADC 時分多工上限。** peripheral ADC sharing 決定跨 array 平行度真實上限；partition group size 必須與 ADC sharing 結構對齊。[E] W3 Hemlet §4.1
15. **在小 GEMM / memory-bound 層硬用 CiM。** CiM integrated cache 不提升 memory-bound 層；小 K GEMM 反而比 baseline 差。[E] L3 Table V
16. **深 pipeline 不計 bubble。** ISAAC 式深 pipeline 在 stride/dependency 下有 bubble；PipeLayer 才引入 parallelism granularity `G`。[E] W1 PipeLayer
17. **在同一份 CIM array 上混跑動態與靜態 weight。** dynamic weight 需第二份 array（ping-pong/pipeline）。[E] L1 §VI-B/§VIII-C
18. **假設 block-FP / 精度不影響 partition。** 精度不對稱會改變 cell 佔用與等效 MAC（IS 下 W/A 不對稱使 MAC 砍半）。[E] L2 p.1198；L5 §II.A
19. **數 8-bit MAC 卻忘了 accumulator 頻寬。** 大量 fold 讓 accumulator buffer 交易成 energy 瓶頸；R 太小反而更差。[E] L2 p.1196/1199
20. **把 reduction 留在跨 die 鏈路上「等之後再優化」。** deadlock 與壅塞會結構性出現；需協定層保證無循環相依。[E] L7 HiRe §IV-D
21. **（R1 新增）忽略稀疏度。** >80% 稀疏的 ReLU 層若不把 ρ 計入有效 K，會高估 fold 與 accumulator 交易；且 skip 粒度必須＝一整條 K 段才省 adder tree。[E] L5-H/L6；R1 §1.1
22. **（R1 新增）用整塊 array 容量當 `C_CIM`。** 必須扣 activation/KV/psum/memory-mode 保留，否則 HS/dual-mode/動態 KV 場景誤判為 model-stationary。[E] L6 Fig.4；W2 CMSwitch；R1 §OG-5
23. **（R1 新增）把「非分割成本優化」計入分割方法數。** low-toggle / center+offset / MDM row 排序 / MacroDimRetile 都是編碼或數值技巧，不切任何維度。[E] R1 §3.2-3
24. **（R2 修正）混淆 K sweet spot（256）與 weight matrix cap（512）。** 兩者不同軸，合併敘述易誤讀。[E] L3 p.1224–25
